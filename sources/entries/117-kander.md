### Entry 117: Kander — terminal kanban that runs parallel coding agents in git worktrees with independent reviewer agents and a delivery gate

- **URL**: https://github.com/dualface/kander (MIT, Go, 120 stars at this read; release v0.9.5, 2026-10-14, single static binary)
- **Date**: 2026-10-14 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2110517015488204973
- **Summary / Key Claims** (upstream README, `kander --help`, embedded rule files): "Strict rule-driven multi-agent parallel development with built-in independent review and delivery gates." Task cards live in a `kanban/` folder inside the repo (git-excluded), each with GOAL, ACCEPTANCE_CRITERIA, THREAT_MODEL, OUT_OF_SCOPE and a RESULT. Agents run in isolated git worktrees in tmux (or herdr) windows; a conflict-aware scheduler checks branch and file overlap before running cards in parallel; two reviewer roles (PMQA and Security) review each card read-only before it can be marked done; card transactions and a durable dispatch protocol cover crash recovery. Supported agent CLIs: Codex, Claude, **Grok**, Cursor, Pi, Devin, OpenCode, Kimi. The author reports 1,726 cards and 1,694 review runs over 68 days, with 49% of review batches finding must-fix issues (upstream's own numbers, not checked here). GitHub issues import through the local `gh` login; it never stores a token.
- **Why it matters here**: the operator wants long unattended Build runs and small decisions handled without him. Today that is one headless Grok Build `/orchestrator` run in a worktree, then Tester and Reviewer bots gate the PR. Kander does the same loop with cards, parallel worktrees, and a reviewer pass inside the loop, and it lists Grok as both an executor and a reviewer (Grok reviewers get read and search tools only). OpenCode is also supported, so a reviewer could run on a local model on nimo and save Bot turns. Compare with Entry 110 (Brigade), 113 (Festival) and 078 (Kanbots).
- **Fit on nimo**: Yes. Single Linux amd64 binary under `~/DEVELOP/pfy-mentat/tmp/kander/`; needs git and tmux. It writes rule files to `~/.agents/kander/` and config to `~/.config/kander/` on first run, so a trial must set `HOME` to a folder under `tmp/` (nimo layout lock). Only `init` writes into a repo (`kanban/` plus a line in `.git/info/exclude`), so run it in a throwaway worktree.
- **Verified on the Grok Bot box** (bubblewrap read-only root, no network, temp HOME and `GH_CONFIG_DIR`): `doctor` printed its environment check and agent table (exit 1, because no agent CLI is on `/usr/bin:/bin`); `init`, `new chore`, `ls`, `show --json` (State `backlog`) and `check` ("ok: 1 tasks") all worked; `show` of an unknown id exited 1. The box's real `~/.agents` and `~/.config/kander` did not appear. No agent was started. The nimo probe is `ops:eval/evq1107/kander/REPORT.md`.
- **Finding**: `doctor` rewrites every rule file from the embedded copy on each run and picks `codex` (falling back to `opencode`) as the default executor and both reviewers, so the first real trial must pick Grok explicitly in the board options. The README says the Linux binary installs with `curl … | tar xz` from `releases/latest`; pin the version and sha256 instead (the smoke does).
