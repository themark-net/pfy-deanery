- **Summary / Key Claims** (upstream README and docs; their claims except where marked verified): a proactive coding agent for one GitHub repository, shipped as a bundle for DeepSeek Harness (DSH). It listens to GitHub notifications (optionally Feishu chats); when an allowed person addresses it, it opens a work item (Ticket), works on it in its own DSH Session and checkout, and answers in the original thread, for example with a pull request. A local web panel (127.0.0.1, port 3082 by default) shows what needs a person. Core principle (`docs/000-philosophy.md`): "take as little human attention as possible, and give as much value as possible": act only when asked or when a team-written rule allows it, speak only when someone must act or can use a result, one structured question at a time, stop by impact rather than effort, report failures honestly. Proactive work starts in an `observe` mode that only records what it would have done. Numbered design docs 000-008 cover domain model, authorization (allowed lists, Mandates, follow-up ownership), execution, prompts, panel, deployment and architecture.
- **Why it matters here**: its authorization and work-item model is a written-down version of what our bot org does informally: an allowed list per source, a Ticket per request with its own session and directory, subscription messages that add context but grant no authority, an `observe` mode before any unasked work, and a panel that only shows what needs Mark. That maps onto pfy-mentat's autonomy loop and the bots' "only ask about material decisions" rule. Design reference first; the docs are the asset.
- **Fit on nimo**: The static check fits (Node 22.19+ or 24+, pnpm, CPU only, no GPU or NVIDIA dependency). Running the agent itself does not fit our rules today: it needs a global `npm install -g @deepseek-ai/dsh@0.2.1-rc.3`, a model provider configured in DSH (hosted DeepSeek or another provider key; local-model support in DSH not checked), a dedicated agent GitHub account, and `gh`/`tmux` wrappers in `~/.local/bin`. Not staged on nimo; the smoke exits 2 there until it is.
- **Verified on the Grok Bot box** (clone under `/tmp`, Node 24.22.1, pnpm 11.7.0 through corepack with `COREPACK_HOME` under `/tmp`): `pnpm install --frozen-lockfile` and `pnpm check` (typecheck, 1197 vitest tests, tsdown build) passed on the first run. The smoke (the same three steps run from `node_modules/.bin`, temp HOME, bwrap with no network) PASSes with one warning: the upstream test `feishu event consumer ... reports a malformed line without stopping` is timing-dependent and failed in 6 of 7 later runs on the box, with and without bwrap.
- **Findings**:
  - Both bundle presets (`dsh-superagent-worker`, `dsh-superagent-router`) run with `danger-full-access` as the operator's OS user; upstream says a worker "can execute programs by path and read the operator's home directory" and recommends a dedicated OS account for isolation. That rules out running it as Mark's user on nimo.
  - Setup requires creating a dedicated GitHub user account for the agent (a GitHub App cannot be the agent because it reads the account's notifications). Account creation is out of scope for bots.
  - `SETUP.md` is written for a coding agent to walk the operator through setup, one question per message with a recommended one-word answer, no secrets in chat, and one plan message before executing. That interview pattern is reusable for pfy-mentat's own onboarding.
  - The bundle changes process-wide `PATH` and git settings in its DSH profile, so upstream keeps it in a separate `superagent` profile.
